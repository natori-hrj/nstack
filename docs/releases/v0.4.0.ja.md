# nstack v0.4.0

[English](v0.4.0.md)

- Go Workflow Core と Codex Adapter を、共通スキル・原則・プレイブック・参照資料・ライセンスを内蔵した Linux の単一バイナリで配布します。実行時に Python・PyYAML は不要です。Python 版は参照実装と回帰検証用に残します。
- Codex の Workflow Support と Native Automation を継続します。実効ロール、独立したサンドボックス内レビュー、ネイティブスキーマ、終了状態、候補そのものに対する品質ゲートと納品の照合を扱います。
- OpenCode v2 に Workflow Support を追加しました。同じスキルを導入し、選択可能なモデルと推論強度で操作者主導の直列ワークフローを使えます。Native Automation、ネイティブスキーマ強制、並列書き込み隔離は対応範囲外です。Claude Code と Grok Build は未対応です。
- 管理された有効化では、検証したスナップショットに原子的に切り替え、ロール・設定・認証情報を上書きしません。従来の Codex ホーム、コマンド、スナップショットを引き続き使えます。有効化前に古い直接配置やプラグインを探索対象から外してください。

[導入](../../README.ja.md) · [OpenCode 設定](../opencode.ja.md) · [移行と切り戻し](../migration.ja.md)。Linux amd64 は実行検証済み、arm64 はクロスビルドのみです。Git、ハーネス、品質ゲート用のコマンドは別途必要です。

将来の Native Adapter: [OpenCode #12](https://github.com/natori-hrj/nstack/issues/12)、[Claude Code #13](https://github.com/natori-hrj/nstack/issues/13)、[Grok Build #14](https://github.com/natori-hrj/nstack/issues/14)。必須能力を実証できた経路だけを登録します。

## GitHub Releases 向け配布物の準備

承認済みのソースと Go 1.27.4 で[ビルド手順](../../README.md#standalone-go-binary)を実行し、独立したクリーンなソースディレクトリでも再ビルドして双方のバイナリをバイト比較します。Linux amd64 を空の `PATH` と使い捨ての設定先で実行し、埋め込み資産と両 MIT 通知を確認します。arm64 のクロスビルドを実機検証とは扱いません。

`nstack-linux-amd64`、`nstack-linux-arm64`、`SHA256SUMS`、`LICENSE`、`LICENSE-upstream` と、名前を区別した [TOML ライセンス](../../vendor/github.com/BurntSushi/toml/COPYING)、[YAML ライセンス](../../vendor/go.yaml.in/yaml/v3/LICENSE)・[NOTICE](../../vendor/go.yaml.in/yaml/v3/NOTICE) を用意し、配布先で `sha256sum -c SHA256SUMS` を実行します。ユーザーホーム、認証情報、個人設定、セッション・テスト出力は含めません。公開用のノートには日英両版を使い、タグ作成と公開は別途明示の許可を得ます。
