# nstack v0.4.0

[日本語](v0.4.0.ja.md)

- The Go Workflow Core and Codex adapter are now available as one Linux executable with embedded skills, principles, playbooks, reference material and notices. Python and PyYAML are no longer runtime dependencies; the Python implementation remains as a reference and regression target.
- Codex retains Workflow Support and Native Automation: effective role checks, independent sandboxed review with a native verdict schema, observed terminal state and exact-candidate quality and delivery checks.
- OpenCode v2 gains Workflow Support: install the same skills, use configurable model/variant choices and apply the operator-led serial workflow. OpenCode Native Automation, native schema enforcement and parallel writer isolation are outside this support tier. Claude Code and Grok Build are unsupported in this release.
- Managed activation selects a verified snapshot atomically without overwriting user role, configuration or authentication files. Existing Codex homes, CLI syntax and snapshots remain supported. Move obsolete direct copies or plugin registrations out of discovery before activation.

See [installation](../../README.md), [OpenCode setup](../opencode.md), and [migration and rollback](../migration.md). Linux amd64 is execution-tested; arm64 is cross-built only. The binary does not bundle Git, the harness, or your quality-gate programs.

Future Native Adapter work remains open: [OpenCode #12](https://github.com/natori-hrj/nstack/issues/12), [Claude Code #13](https://github.com/natori-hrj/nstack/issues/13), and [Grok Build #14](https://github.com/natori-hrj/nstack/issues/14). Registration requires each route to demonstrate its mandatory capabilities.

## Prepare GitHub Releases assets

From the exact approved source, use Go 1.27.4 and the [reproducible build commands](../../README.md#standalone-go-binary). Repeat in an independent clean source directory and compare both binaries byte-for-byte. Run the Linux amd64 binary with empty PATH and disposable harness homes; verify the embedded assets and both MIT notices. Cross-building arm64 is not an execution test.

Prepare `nstack-linux-amd64`, `nstack-linux-arm64`, `SHA256SUMS`, `LICENSE`, `LICENSE-upstream`, and the vendored [TOML license](../../vendor/github.com/BurntSushi/toml/COPYING), [YAML license](../../vendor/go.yaml.in/yaml/v3/LICENSE) and [YAML notice](../../vendor/go.yaml.in/yaml/v3/NOTICE) with distinct filenames. Verify `sha256sum -c SHA256SUMS` in the asset directory. Do not include home directories, credentials, host config, or session/test output. Use both language versions of these notes when publishing. Keep preparation separate from tagging and publication, which require explicit authorization.
