# ホストアダプター

[English](adapters.md)

`skills/` の Markdown が受け入れ、操作権限、担当、レビュー予算、候補の証跡を定義します。アダプターはこの契約をホスト固有の操作に対応づけます。各操作にはプロジェクトの指示と実効権限が適用されます。

| 操作 | アダプター契約 | Codex | Cursor / Claude Code / OpenCode |
|---|---|---|---|
| 検出 | 同じ手順を導入・起動し、実際に読み込まれたパスを確認する | ネイティブスキルとプラグイン | nstack で未評価 |
| ロール | 起動前にロール・モデル・推論強度・アクセスを確認する | エージェント TOML とモデル一覧 | 未評価 |
| 隔離 | レビューを読み取り専用とし、並行作業者ごとに書き込み範囲を分ける | ネイティブサンドボックス、別セッションと worktree | 未評価 |
| 再開・停止 | ホスト固有の操作を使い、worktree と revision の証跡を残す | Codex CLI またはセッションを提供するクライアント | 未評価 |
| 納品 | 承認範囲内で Git・PR 操作を行い、証跡を候補 SHA に結びつける | Git と利用可能な GitHub ツール | ホストでの確認が必要 |

書き込みの隔離が取れなければ直列に実行します。必須のレビュー、権限、プロバイダーのアクセスが不足している場合は、確認済みの証跡と阻害要因を報告します。対応を表明する前に、実際のホストで起動、権限、受け入れ条件を確認します。現在は [Codex アダプター](codex.ja.md) を配布しています。

納品候補には基点 SHA、候補 SHA、各ゲートのコマンドと結果、レビュアーとレビュー済み SHA、残る制約を記録します。PR head と検証済みのローカル SHA が一致することを確認します。head が変わった場合は影響する振る舞いを再検証します。コミット、フィーチャーブランチへの push、PR 作成、個別承認が必要な操作はリポジトリとホストの規則に従います。

`adapters/review_workflow.py` はアダプターの `preflight`、`gate`、`run` を呼び出します。アダプターは選択モデルと権限を確立できない場合に失敗し、レビューごとにコンテキストを分離して読み取り専用を強制し、スレッド・セッションの証跡と構造化された判定を返します。Git 操作、候補への証跡の紐づけ、レビュー予算、承認済みの納品はホストが管理します。Codex アダプターはネイティブ app-server プロトコルを使います。
