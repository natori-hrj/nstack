# nstack v0.3.0 commands / コマンド集

[Release notes / リリースノート](releases/v0.3.0.md)

## Install or upgrade / 導入・更新

Use Python 3.11 or later, PyYAML and Codex CLI 0.172.0. Run after v0.3.0 has been published. For a legacy direct or plugin install, follow the [migration guide](migration.md) before activation. Existing role TOMLs stay in place.

Python 3.11 以降、PyYAML、Codex CLI 0.172.0 が必要です。v0.3.0 公開後に実行します。旧版の直接配置やプラグインから移行する場合は、有効化前に[移行ガイド](migration.ja.md)に従ってください。既存のロール TOML は保持されます。切り替え前に Codex セッションを閉じ、表示された旧スナップショット ID を控えてください。

```sh
(
  set -eu
  config_dir="${CODEX_HOME:-$HOME/.codex}"
  git clone --branch v0.3.0 https://github.com/natori-hrj/nstack.git "$HOME/nstack-v0.3.0"
  cd "$HOME/nstack-v0.3.0"
  python3 tests/validate.py
  if [ -L "$config_dir/skills/nstack-managed" ]; then
    previous="$(readlink "$config_dir/skills/nstack-managed")"
    previous="${previous%/skills}"
    printf 'Previous snapshot ID: %s\n' "${previous##*/}"
  fi
  revision="$(git rev-parse HEAD)"
  python3 adapters/codex/install.py --home "$config_dir" stage "$revision"
  python3 adapters/codex/install.py --home "$config_dir" activate "$revision"
  mkdir -p "$config_dir/agents"
  for agent in examples/agents/*.toml; do
    dest="$config_dir/agents/${agent##*/}"
    if [ ! -e "$dest" ] && [ ! -L "$dest" ]; then
      (set -C; cat "$agent" > "$dest")
    fi
  done
)
```

Open a new session and run `$setup-nstack` to confirm discovery and the intended role assignments. / 新しいセッションで `$setup-nstack` を実行し、検出とロールの割り当てを確認します。

## Automated implementation and independent review / 自動実装と独立レビュー

Run from a clean nstack development checkout with an authenticated Codex CLI. The command prompts for the task and observable acceptance criteria on one line. It authorizes a new local work ref and saves evidence outside the checkout.

認証済みの Codex CLI が使えるクリーンな nstack 開発チェックアウトで実行します。依頼と観測可能な受け入れ条件を1行で入力します。書き込み先は新規ローカル ref で、証跡はチェックアウト外に保存します。

```sh
(
  set -eu
  run="$(mktemp -d "$HOME/nstack-implementation.XXXXXX")"
  printf 'Task and acceptance criteria: '
  IFS= read -r task
  printf '%s\n' "$task" > "$run/brief.md"
  printf 'Evidence: %s\n' "$run/evidence"
  python3 adapters/codex/review.py --authorize-host \
    --repo "$PWD" --base "$(git rev-parse HEAD)" \
    --work-ref "refs/heads/nstack-work-${run##*.}" \
    --brief "$run/brief.md" --evidence "$run/evidence" \
    --implement-model gpt-6.2-sol --review-model gpt-6.2-astra \
    -- python3 tests/validate.py
)
```

## Review-first remediation / レビュー先行の自動修正

Run in the clean checkout containing the candidate. Enter its comparison base SHA, then the acceptance criteria. A passing initial review leaves HEAD unchanged. At most two remediation rounds can run locally. These examples authorize local work only.

候補を含むクリーンなチェックアウトで、比較基点 SHA と受け入れ条件を入力します。最初のレビューで合格した場合は HEAD を変更しません。ローカルで最大2巡の修正を行います。この例の許可範囲はローカル作業です。

```sh
(
  set -eu
  run="$(mktemp -d "$HOME/nstack-review-first.XXXXXX")"
  printf 'Comparison base SHA: '
  IFS= read -r base
  printf 'Acceptance criteria: '
  IFS= read -r task
  printf '%s\n' "$task" > "$run/brief.md"
  printf 'Evidence: %s\n' "$run/evidence"
  python3 adapters/codex/review.py --authorize-host --review-first \
    --repo "$PWD" --base "$base" --work-ref "refs/heads/nstack-work-${run##*.}" \
    --brief "$run/brief.md" --evidence "$run/evidence" --max-remediations 2 \
    --implement-model gpt-6.2-sol --review-model gpt-6.2-astra \
    -- python3 tests/validate.py
)
```

## Roll back / 切り戻し

Close active sessions and enter the snapshot ID recorded during upgrade. For a legacy installation, restore the backup using the migration guide.

セッションを閉じ、更新時に控えた旧スナップショット ID を入力します。旧来の直接配置やプラグインへの切り戻しは移行ガイドを使います。

```sh
(
  set -eu
  cd "$HOME/nstack-v0.3.0"
  printf 'Previous snapshot ID: '
  IFS= read -r previous
  python3 adapters/codex/install.py --home "${CODEX_HOME:-$HOME/.codex}" activate "$previous"
)
```

## Release operator / リリース担当者

Use only after explicit publication approval and after PR #6 is merged. Set `NSTACK_VERIFIED_HEAD` to the full release-preparation SHA that passed CI. The release target must be on `main` with the same tree as the verified head.

明示的な公開承認を得て PR #6 をマージした後にだけ実行します。`NSTACK_VERIFIED_HEAD` に CI を通過したリリース準備候補の完全な SHA を設定します。リリース対象は `main` 上にあり、検証済み head と同じツリーである必要があります。

```sh
(
  set -eu
  repo=github.com/natori-hrj/nstack
  url=https://github.com/natori-hrj/nstack.git
  tag=v0.3.0
  head="${NSTACK_VERIFIED_HEAD:?Set the approved and CI-verified PR head SHA}"
  pr="$(gh pr view 6 --repo "$repo" --json state,headRefOid,mergeCommit)"
  test "$(printf '%s' "$pr" | jq -r .state)" = MERGED
  test "$(printf '%s' "$pr" | jq -r .headRefOid)" = "$head"
  merged="$(printf '%s' "$pr" | jq -er '.mergeCommit.oid')"
  passed="$(gh run list --repo "$repo" --workflow offline-verification.yml \
    --commit "$head" --event pull_request --json conclusion --jq 'any(.[]; .conclusion == "success")')"
  test "$passed" = true
  git fetch --no-tags "$url" refs/pull/6/head
  git fetch --no-tags "$url" refs/heads/main
  git merge-base --is-ancestor "$merged" FETCH_HEAD
  test "$(git rev-parse "$head^{tree}")" = "$(git rev-parse "$merged^{tree}")"
  existing="$(git ls-remote --refs "$url" "refs/tags/$tag")"
  test -z "$existing"
  notes="$(mktemp)"
  git show "$merged:docs/releases/v0.3.0.md" > "$notes"
  gh release create "$tag" --repo "$repo" --target "$merged" \
    --title "nstack v0.3.0" --notes-file "$notes"
)
```
